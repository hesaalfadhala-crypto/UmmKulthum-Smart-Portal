# استيراد استمارات الزيارات من PDF

الواجهة: `visit-import.html`، مرتبطة بزر في `visits.html`.

## التشغيل

- حساب مديرة، مديرة مساعدة، معلمة أولى أو منسقة، مع صلاحية كتابة كاملة للمعلمة/القسم وفق `observation_private.teacher_access` الحالية.
- ملف PDF حتى 50 MiB و100 صفحة؛ الاستمارات متتابعة، صفحة أو صفحتان لكل استمارة حسب اختيار المستخدمة.
- الملف الأصلي في bucket خاص `classroom-visit-imports`، حسب مالكة الرفع، مع سجل تدقيق منفصل عن اسم الزائرة.
- لا تحفظ نتيجة النموذج زيارةً تلقائيًا. المطابقة التلقائية للأسماء الكاملة المطابقة فقط، مع مراجعة إلزامية لجميع المعايير قبل الاعتماد. الأصل يفتح بجانب البيانات.
- الخانات غير الواضحة تبقى فارغة ويُمنع الاعتماد حتى تصحيحها. لا يُستنتج الحكم النهائي من الدرجات.
- الاستمارات المتطابقة للمعلمة والتاريخ والزائرة والدرس لا تتكرر. استمارات الزائرات المختلفات مستقلة. التشابه القريب يتوقف للمراجعة دون تعديل الزيارات السابقة.

## تفعيل قراءة الخط اليدوي

دالة `extract-classroom-visits` منشورة. تحتاج سر الخادم `OPENAI_API_KEY` في Supabase Dashboard → Edge Functions → Secrets، بمفتاح مشروع OpenAI ذي رصيد API. لا تضعي المفتاح في GitHub أو الواجهة أو المحادثات.

النموذج الافتراضي المثبت `gpt-4.1-mini-2025-04-14`؛ يمكن تحديد `CLASSROOM_PDF_MODEL` بسر خادم آخر إذا احتاجت المدرسة نموذجًا آخر. تستهلك القراءة رصيد API، وتُرسل أجزاء الاستمارة فقط إلى OpenAI مع `store:false`. هناك سقف 100 طلب/24 ساعة لكل مستخدمة، و60 محاولة لكل ملف، وحد 4 صفحات/طلب. لا تُحفظ بيانات النموذج في سجلات الخادم.

`GET /functions/v1/extract-classroom-visits/status` يعرض حالة الإعداد boolean فقط دون بيانات مستخدمات. كل قراءة PDF تستلزم `auth.getUser()` حيًا وصلاحيات استيراد صالحة وملفًا مملوكًا للمستخدمة. `verify_jwt=false` مقصود لأن التحقق من الهوية يجري داخل الدالة؛ هذا يدعم مفاتيح Supabase العامة الحديثة دون إتاحة القراءة المجهولة.

عند غياب المفتاح تعرض الواجهة أن القراءة التلقائية بانتظار التفعيل؛ يظل رفع الأصل والمراجعة والإدخال اليدوي متاحًا. لا يُعرض نجاح وهمي للاستخراج.

## الاستئناف والتحقق

- النتائج الوسيطة وصفحات القراءة محفوظة في `classroom_import_batches`. افتحي الملف من «الملفات المحفوظة» لاستكمال القراءة أو المراجعة.
- كل اعتماد ذري يسجل `classroom_import_records` مع المستخدمة المعتمدة، الزائرة، بصمة الملف وصفحات المصدر والنسخة التي تمت مراجعتها.
- تشغيل: `node --test tests/visits/import.test.mjs tests/visits/import-ui.test.mjs`.
- اختبارات Postgres المعزولة تغطي RLS، إسناد الزائرة، التأكيد الإلزامي، الدرجات الناقصة، منع التكرار، إعادة المحاولة والتحليل. اختبار DOM يغطي الاستئناف والمراجعة وإلغاء التأكيد بعد أي تعديل.
- اختبارات التصدير القديمة في `tests/visits/exports.test.mjs` تتوقع صفحة واحدة ويُنتج renderer الحالي صفحتين في هذه البيئة؛ ملفات renderer والتصدير لم تتغير ضمن هذا العمل.
- بعد إضافة المفتاح يجب اختبار ملف اصطناعي خالٍ من بيانات حقيقية من الرفع إلى القراءة والمراجعة والاعتماد، ثم اختبار استمارة خط يد معروفة للتأكد من جودة النسخ. لا تُعتبر قراءة الخط اليدوي مختبرة قبل ذلك.
